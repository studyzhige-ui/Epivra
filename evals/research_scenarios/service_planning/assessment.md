# 青屿晚间服务：评测合同 v1

本文件是**评测侧材料**，不得放入被测系统授权资料目录，不得进入调查、写作或产品核查者的上下文。语料及本合同由编码 Agent 编写，尚需独立复核；不声称人类专家认证、公开基准或现实机构事实。该版本在首次模型运行前制定。若发现题目错误，应保留旧版本和原结果，说明修订原因，再评估受影响项；不能为迁就某一次输出暗中改分。

## 1. 场景目的与边界

这是正常的封闭资料决策研究：九份连续叙述的组织文件，包含任务背景、口径说明、调查、运营、体验、财务、执行和利益相关者意见。需要组合信息形成选择及实施建议，不是从四句话找一个陷阱。内容均为 synthetic。它用于本地功能与研究回归，不代替公开基准，不估计现实世界通用能力，也不能凭一次成功宣布产品成熟。

任务允许推荐A、B、C、预约活动或有依据的组合。不存在预设优胜者。不得因为推荐与评审偏好不同、标题不同、未计算非必要数字，或没有逐段使用规定模板而扣分。报告无需复述九份材料的全部细节。

事实、报告质量、角色行为、协作和工程运行分别记录；某个维度未观察到，标为**未验证/不适用**，不得写成失败。局部瑕疵应按其是否影响决策区分轻微与实质，不以任意单项问题自动判整题失败。

## 4. 报告评价：先分维度，后整体判断

每一维记录：充分 / 部分充分 / 有实质问题 / 未验证，并引用报告位置和来源依据。评审理由需要自己成立，不能仅重复标签。若用模型评审，保存模型、提示、原始理由与配置；评审模型的意见不是最终事实。

1. **完成委托。** 有清楚建议与可行备选，服务委员会决策，覆盖需求、试点、资源、执行及复盘；不要求每项独立成章。只总结材料而不给任何建议属任务缺口。
2. **证据准确。** 关键人数、金额、口径、来源关系正确；不虚构额外材料，不把意向或意见当作已发生事实。细小、不影响论证的笔误与改变建议的错误分别记录。
3. **解释适度。** 可将观察和体验作为有用证据，不因缺少随机实验就否认价值；也不声称已经证明学习成果改善、总体需求精确比例。承认有限外推，同时能给出条件性决策。
4. **形成综合。** 将成本与服务内容、现金与执行准备、参与便利与资源分配结合，而不是只按价格排序。允许不同价值权重，只需显式且与委托一致。
5. **行动可用。** 推荐方案在18万元及现有约束下可解释；未落实人员、南站额外场地等以条件处理。有实际启动和复盘安排，不强求完整项目管理制度或特定指标阈值。
6. **表达与可回查。** 读者能分清事实、条件和建议；重要判断有原文入口。引用形式不唯一，不要求每句引文。不得以机械引用覆盖率替代支持关系。

整体结论采用：**可用于讨论 / 需实质修订 / 无法判断**，附主要理由与最小必要修改。不把“没有写我喜欢的指标”当作实质缺陷，不使用所有细目必须满分的隐藏标准。若希望计算数值分数，应在运行前另行冻结权重，不能见到结果后追加。

## 5. 角色合同的观察方式

以完整小任务的实际输入、工具轨迹和交付评价，不能仅靠最终报告猜测某个角色失败。职责执行与语义正确分开记录。

| 角色 | 本场景可以观察什么 | 什么不算失败 |
| --- | --- | --- |
| 负责人 | 将委托拆为有意义子问题，保留预算和决策边界，直接分发已有成果，处理有影响的缺口 | 不采用固定角色数；无需自己重复查每份材料 |
| 调查者 | 回答分配的完整子问题，读相关原文，交付依据、计算及必要限制 | 不调查任务外的一切；无需逐URL追加核查调用 |
| 综合者 | 如被使用，整合需求、方案与条件，解决会影响建议的交叉矛盾 | 本次未使用综合者标不适用，不强制增设阶段 |
| 作者 | 直接接收研究成果，写成满足委托的报告，保留推断边界 | 不重做所有调查；无需复述所有细节 |
| 核查者 | 针对完整交付及重要依据判断实质问题，理由可回查 | 不逐段写固定格式审查；不对每个正确来源重复提取 |

自查可以体现在完整交付本身和可观察动作中，不要求披露私有推理，也不强制单独付费模型调用。无可观察证据时，不伪称已证明执行了内部思考。

## 6. 协作与 Harness 的分离评价

协作检查：输入是否为原始用户需求与直接生产者产物；引用能否回到正确版本和来源；必要限制是否直接保留；接收者是否知道任务范围与交付用途；只有出现具体缺口、冲突或新推导需要时才回查/澄清；澄清后是否接续有效工作。不能把合理的来源阅读都计为浪费，重复调用需要结合目的判断。

工程检查：工具响应是否可靠保存与可读；已完成工具或付费调用恢复时是否回放；暂停/恢复/改向是否遵守状态与权限；旧方向产物不会被误认为当前承诺。**本任务未主动触发的工程行为标未验证，应由确定性测试负责，不靠自编研究文本模拟通过。** 正常闭环出现供应商阻断时，将工程中断与报告能力分开，不给没机会完成的角色判失败。

不预设必须发生冲突、必须开澄清、必须暂停、必须读取九份文件各若干次或必须调用五个角色。评测应观察系统为完成这项真实任务做出的必要工作，不诱导仪式性步骤。

## 7. 首次运行前的检查与结果保存

运行前核对九份授权原文、文件摘要、任务版本、代码版本、模型及可观察供应商配置；确认assessment不在授权范围。保存审批事件、产物及调用轨迹。不要通过把评分项交给产品核查者提高成绩。

先由独立审查确认题目自洽和算术，再做少量完整运行；若修改实现，应报告修改前后版本和调用成本，不将不同模型的一次输出当作稳定优劣。后续可以增加其他体裁及更长真实授权资料；本场景没有验证开放搜索和解析复杂布局，也不构成向100份资料规模扩展的全部依据。
