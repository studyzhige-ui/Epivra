# Agent 自主取证与精确修订能力：实现与真实对照

日期：2026-09-20。开发仅在 `improve/epivra-optimization`；不合并 main、不发布。

**结论：能力实现和严格离线回归已完成，但本次真实对照没有证明整体效率提升。** 新工具不是速度或质量的保证，两个原始评测作业均保留失败状态。以下改动是尚未通过完整产品效率验收的候选能力。

## 1. 增强 Agent 的行动能力，不替代它的判断

- `search_sources`：Agent 决定字面词/短语和来源范围，在本研究已保存的原文中定位多个片段，收到精确位置、前后文、来源与可保存的 selection。不新增网络请求、不用摘要替代原文、不声称字面检索已经找全证据；无命中不代表不存在，仍可改词或读完整资料。调查者、综合者、作者、reviewer 可用，lead 的既有原文权限不变。
- `read_manuscript` / `revise_report`：作者取得带原始引用标记的可编辑稿件，自主决定每个替换及受影响范围，宿主只执行精确修改并生成新不可变版本。未改内容原样保留；歧义、重叠、无效引用在写入前失败。旧稿与旧 review 不覆盖，新稿仍需绑定新核查；Agent 仍可选择整体 draft_report，不强制局部编辑。
- draft 与 revision 统一使用原子报告/成果提交，避免回执失败留下半份报告。

COMMON、WRITING_GUIDES、ResearchService 和调度策略未改；除工具说明外，只在 writer 说明中加入可选精确修订入口。没有固定研究流水线、主题规则、强制首回合动作、自动接受/发布、默认报告长度或生产研究总量上限。

## 2. 严格测试与一次模型可见合同修复

初始增加10项确定性测试，覆盖原文范围/Unicode/页游标、同 work selection、角色与研究隔离、引用往返、同时精确编辑、错误不留半成报告等。

真实使用出现一项搜索输入被拒绝：执行端限定1–16个非空字面词、每项至多200字符，而 Schema 尚未完整展示该限制。这是新增工具的合同缺口，不归咎模型。已补 `maxItems` / `maxLength`、参数路径反馈及第11项离线测试。原始失败不改写，未追加付费重跑。该限制只约束一次检索工具参数，不限制查询次数、研究深度或报告篇幅。

严格CI也揭示此前测试语法错误、settle失败注入mock未接收timing关键字和import排序问题；保留断言修正兼容性。PowerShell多条native命令可能让前面的失败被后续成功覆盖，本批四个工作流逐条检查退出码，不以“页面显示绿”替代测试日志。

运行35464409459，代码80d25af：**448项测试，446通过、2跳过；架构检查、Ruff、配置内4文件mypy、wheel构建全部成功。** 这不是所有平台/扩展或洁净wheel安装证明。参数合同补齐后增加第449项测试，最终提交的CI以对应新运行及PR验收评论为准。开发过程中出现的mock、import及新编辑累加器mypy错误均保留，未降低检查范围。

两份修订稿均将登记人数+20%与未测量的活动效果分开，并保留120/100、三场、每场3000和总9000。它们在主要事实纠正上可用，不代表每条写作表达均理想。候选仍调用了没有用户长度要求的measure_text，后续应从真实输入和决策定位原因，而非给所有任务叠加禁令。

**没有证明速度改善。** 不以候选总token下降掩盖交付差异；也不把一次随机试验解释为稳定退化。继续开发须针对通用决策/输入问题，而不是强迫Agent完成本次题目的预设动作。
