# 发布前五项收尾：通用研究指令、任务上下文与依据同步

日期：2026-09-21。起点为优化分支 `cf7691941e4986e872b31c8b6d79b0b6da8e2114`。

本批明确不做按供应商、模型名、模型等级或推理参数分支的提示词。`PROMPT_VERSION=research-collaboration-20260921` 是跨厂商共用版本，模型适配器及模型配置均未改动。初始路线与已批准研究的不同说明来自产品阶段，而非模型调优。

## 实际修改

### 1. 判断、依据、稿件同步

保留现有 `record_finding(replaces=...)`：一条研究判断的 statement、status、support、conditions 和 limits 一起产生新版本，历史不覆盖。工具说明明确要求修正时保留仍成立的条件，不能只修改文稿而让错误 finding 继续作为当前依据。修正回执现在同时返回替代关系和写作依据是否过期。

`patch_draft` 支持两种明确模式：

- 提供 edits：针对同一 base 一次应用所有可一起完成的精确修改。
- **省略 edits，并显式提供不同的新 basis**：正文和 evidence 保持不变，仅生成新的依据绑定版本，回执 mode=basis_rebind、edit_count=0。

第二种模式不是空补丁绕过。要求已有当前文稿、新依据有效且仍覆盖原引用；禁止空 edits、相同依据的无变化保存、隐式修改证据集合。仍执行基稿CAS、原子报告/回执、操作幂等和发布权限检查；新版本不继承旧审核。该能力不判断文字在语义上是否已经正确，这仍由研究主体和编辑负责。

### 2. 编辑分级及反馈合并

共用规则区分三类情况：文稿表述错误、当前研究依据本身错误、不改变含义和用途的建议。重要事实、成立条件、建议或用户明确要求的错误不能因为只需改一个字就降为 comment；准确限定、真实未知或已查明的真实分歧也不能被无理由拒绝。

编辑集中整理已经确认的问题，合并共同原因，注明原文差别与影响范围。提交前核对 reason/defects/comments 自洽，不得一边承认关键判断无依据一边接受。示例为跨主题的正反条件，不包含原设备题的答案或专用规则，不要求导出隐藏推理。

### 3. 合理委派与干净上下文

主体不再遵循“自己会做就不委派”的含糊倾向。按独立性、并行收益、局部上下文价值、共享状态和协调成本选择助手。具体独立核实、相互独立的调查方向、大量只在局部有用的工具输出可使用助手；已知读取、简单算术、紧密连续推导及同稿关联修改通常直接完成。该规则不取消独立最终编辑。

助手任务携带问题、必要背景、真实范围及相关原始引用，不携带预定答案。已委派问题不重复做；有独立工作就继续，没有可推进工作才 wait_for_work；不轮询私有轨迹、不预测助手结果。

`_focused_research_refs` 沿显式交接和本助手记忆中的研究引用查找相关 finding、冲突、note 和成果，并带入被替代记录的更新版本。调查/冲突助手不再自动装入全体 writing_basis findings，也不在默认目录页灌入无关结论。原用户问题、批准路线与授权保持；全局资料仍可通过显式 read_context/find_artifacts/read_source 按需读取。它是输入选择，不是权限隔离或“上下文一定无偏”的保证。

最终编辑与全稿写作者继续获得其完整对应写作依据。Synthesizer 原文权限和授权内补查工具保持不变。

### 4. 成批读取与编辑

明确独立且参数已知的读取可同轮完成；依赖工具结果的动作不能提前猜测。先理解本轮问题及语义影响，再用一批 patch_draft 修改相关摘要、表格、正文和建议。定位上下文小而唯一，不代表只改一两行。对共享基稿的相关修改不能并发抢写；冲突后读最新稿再判断。

本批不改变报告长度、不限制研究深度、不要求一次修改解决未知问题，也不跳过对当前精确稿件的独立核查。

### 5. 统一规范提示词与阶段合同

`TOOLS` 只有一个生效定义，删除被后续 update 覆盖的旧说明。共同原则、各能力职责、写作修订和编辑分级分段明确。批准前实际加载 ROUTE_PROMPT，不把已经批准阶段的研究行动说明一并注入；批准后加载完整主体说明。`phase` 与 `prompt_version` 保存在真实模型请求中供审计。

不提出研究假设、不预定答案、批准后不向用户请示、无默认报告篇幅限制继续成立。工具合同说明与实际 schema、权限一致，错误回到 Agent，不放宽权限迁就错误调用。

## 兼容性与工程范围

无新增依赖、无新服务、无数据库结构迁移、无新多Agent框架、无供应商专属prompt。现有 continuous-research-v2 文稿及旧带 edits 的 patch 调用继续有效；历史记录不被重写。新的 prompt 会影响后续新决策，已经保存的请求/结果保持原样，不重发结果未知的调用。

历史 R1 writer 对照依赖原段落字节身份。其测试现在同时验证固定旧段落上的替换行为和当前生产prompt变化后的拒绝；不把旧结果悄悄重新标成新prompt成绩。复现旧实验应使用原提交。

## 验收入口

新增 `tests/test_final_pass.py` 的20项检查：仅依据更新、正文/引用不变、无变化拒绝、陈旧版本/错误来源拒绝、独立审核不能跨版本、原子回滚、幂等重放及重启、助手权限、修正回执、局部上下文、冲突引用追踪、显式共享资料访问、全稿依据保持、阶段实际提示词及四种供应商identity的共同指令。

既有16,000字符上下文压力与证据锚点回归保持，不扩大测试容量。最初候选的提示信息略超窗口，已通过去除重复工具说明与冗长元数据修正；原批准路线仍进入助手输入，不为了干净上下文丢失用户策略。

这些是机制测试，不证明模型一定作出正确协作选择、没有幻觉或已经获得真实研究提速。正式收尾仍须在依赖完整环境执行全部测试、Ruff、mypy、构建和真实任务检查。配套交付证据区分本轮实际完成与未执行项，不将上一次Windows CI用作本轮验收。
